## 3. 买什么

### 服务器

| 项目 | 建议 | 说明 |
|------|------|------|
| 配置 | **2 核 2G / 40G 硬盘 / 3M 带宽** | 单人用绰绰有余，其实 1核1G 也够，但 2G 留点余量更省心 |
| 类型 | 轻量应用服务器（腾讯云 / 阿里云都行） | 比云服务器 CVM/ECS 便宜，够用 |
| 系统 | **Ubuntu 22.04 或 24.04 LTS** | 脚本按这个写的，最省事 |
| 地域 | 见下方【备案】一节 | |

### 域名

普通域名就行（`.com` / `.cn` / `.top`）。**不需要买贵的。**

### 费用大致量级

- 轻量服务器：有活动时常见 ¥100/年 上下，常规续费大约 ¥60～80/月
- 域名：¥30～70/年

价格随时在变，以你实际下单页面为准。

### ⚠️ 关键取舍：备案

| 方案 | 服务器地域 | 要不要备案 | 上线速度 | 网络质量 |
|------|-----------|-----------|----------|----------|
| A | **中国香港 / 境外** | 不用备案 | **当天就能用** | 白天好，晚间跨境可能偏慢（对单人打卡影响不大） |
| B | **中国大陆**（上海/广州） | **必须备案** | **要等 1～2 周** | 最快最稳 |

**我的建议**：
- 你如果急着在外面用 → 先选香港，当天上线。以后想要更稳再换大陆。
- 你如果不着急、想要最好的体验 → 直接大陆 + 备案，等两周。

> 注意：备案要求域名和服务器匹配。香港服务器不能用大陆备案号。所以这个选择要在买之前定。

## 4. 部署步骤

### 4.1 先把域名指向服务器（最容易漏，先做，因为要等）

买完域名后，去**域名管理后台**（在你买域名的那个网站上）加一条**解析记录**：

| 填什么 | 填成 |
|--------|------|
| 记录类型 | `A` |
| 主机记录 | `@`（表示根域名 `kaoyan.com`；想用 `www.kaoyan.com` 就填 `www`） |
| 记录值 | **你服务器的公网 IP** |
| TTL | `600`（或默认值） |

保存即可，不用重启任何东西。**解析生效通常几分钟，最长几小时。**

> **为什么这一步必须最先做**：HTTPS 证书是 Let's Encrypt 来签发的，它会先来访问 `你的域名` 确认「这个域名真的指向那台服务器」。解析没生效，证书就签不下来，浏览器会报「证书错误」—— 而这个报错**完全看不出真正原因是 DNS**。所以部署脚本现在会先预检解析，不通过就停下来明确告诉你。

验证解析是否生效（在你自己电脑上执行，把域名换成你的）：

```bash
nslookup 你的域名
```

返回的 `Address` 应该就是你的服务器 IP。

---

### 4.2 先做一次免密登录（只做一次，1 分钟）

这样后续所有操作我都不需要你的密码 —— 更安全，也不用手动敲命令。

```bash
# 在你电脑上生成一把专用密钥
ssh-keygen -t ed25519 -f ~/.ssh/kaoyan_deploy -N ""

# 把生成的公钥内容打印出来
cat ~/.ssh/kaoyan_deploy.pub
```

把打印出来的那一行（`ssh-ed25519 AAAA...` 开头）贴到服务器的 `~/.ssh/authorized_keys` 里。
两种贴法，任选：

- **云厂商控制台**：多数轻量服务器有「密钥 / 登录凭据」的网页管理入口，直接粘贴
- **服务器网页终端**：登录进去执行 `mkdir -p ~/.ssh && echo '你复制的那一行' >> ~/.ssh/authorized_keys && chmod 600 ~/.ssh/authorized_keys`

验证一下通不通：

```bash
ssh -i ~/.ssh/kaoyan_deploy root@<服务器IP> 'echo ok'
```

> 如果你不想折腾密钥，也可以直接把 root 密码给我 —— 但那样我每次操作都得用到密码，
> 而且密码会出现在会话里。密钥方式明显更好。**部署完成后建议把密码登录关掉。**

### 4.3 一条命令跑完

```bash
bash deploy/deploy_from_local.sh \
    --host <服务器IP> \
    --domain kaoyan.example.com \
    --email 你的邮箱@example.com \
    --key ~/.ssh/kaoyan_deploy
```

这条命令会依次完成：

| 步骤 | 做什么 |
|------|--------|
| ① | 打包上传代码（**不含 `.env` 和 `data/`**，不会泄露密钥、不会覆盖线上数据） |
| ② | 在服务器上装 Python 环境、依赖、装 Caddy |
| ③ | 把家里的学习数据用 **SQLite 在线备份**导出后传上去，并校验完整性 |
| ④ | 下发 systemd 服务、开机自启、HTTPS 证书、每日备份 |
| ⑤ | 重启服务，然后本机 + 外网各跑一遍自检并打印结果 |

### 4.4 最后一步：确认登录门生效

系统用「账号 + 密码」登录。部署脚本已经把初始化码准备好，**你只要确认一件事：打开网站出的是登录页，不是内容页。**

```bash
ssh -i ~/.ssh/kaoyan_deploy root@<服务器IP>

# 看系统自动生成的「首个账号初始化码」
cat /opt/kaoyan/data/setup_code.txt
```

> 不想用自动生成的？自己指定一个，再重启：
> `echo "SETUP_CODE=$(openssl rand -base64 12)" >> /opt/kaoyan/.env && systemctl restart kaoyan`
> 优先级是 `SETUP_CODE` > `ACCESS_PASSWORD` > 自动生成。

**第一次打开网站**会引导你创建管理员账号 —— 那就是你自己。之后给你那 2-3 个熟人
开号有两条路，用哪条都行：

- **让他们自己申请**：把 `https://你的域名/register` 发给他们，他们自己填用户名密码；
  提交后**还登不进去**，你在 **设置 → 用户管理** 顶部的「N 条申请待批准」里点「批准」才生效。
  不认识的人点「拒绝」（账号删除、用户名释放）。不想开放注册就设 `ALLOW_SELF_REGISTER=0`。
- **你直接开**：**设置 → 用户管理 → 添加账号**，建好即可用。

两种方式建出来的号都是**每人一套账号密码、数据互相看不见**。
建号之后初始化码自动失效，不用管它。

> 完全不想用账号体系也行：在 `.env` 里设 `ACCESS_PASSWORD=一个口令`，并且一个账号都不建，
> 系统就退回成"大家共用一个口令、共用一份数据"的老样子。

**登录门没生效就别对公网开放。** 这是部署流程里唯一需要你亲眼确认的一步。

### 4.5 备选：全部手动

不想让我碰服务器，就照着手动流程做，脚本里每一步都是独立的：

```bash
# ① 服务器初始化（幂等，可以反复跑）
bash deploy/setup_server.sh --domain kaoyan.example.com

# ② 上传代码 + 数据（从你电脑执行）
scp -r app web seeds tools deploy requirements.txt root@<服务器IP>:/opt/kaoyan/
scp data/app.db root@<服务器IP>:/opt/kaoyan/data/app.db

# ③ 配置环境变量（务必填 AI_API_KEY；登录初始化码可留空，系统会自动生成）
cp /opt/kaoyan/deploy/env.production.example /opt/kaoyan/.env
vi /opt/kaoyan/.env

# ④ 启动
systemctl enable --now kaoyan

# ⑤ 配每日备份
cp /opt/kaoyan/deploy/kaoyan-backup.{service,timer} /etc/systemd/system/
systemctl enable --now kaoyan-backup.timer

# ⑥ 验证
bash tools/_auth_test.py    # 把文件里的地址改成你的域名再跑
```

## 5. 上线之后怎么用（这条最重要）

**统一用一个网址，不要再开本机那个。**

- 手机、平板、家里的电脑 —— 全部访问 `https://你的域名`
- 家里的电脑就退化成一台普通浏览器客户端，不再自己跑服务

为什么必须这样：SQLite 是**单机数据库**，如果家里一份、服务器一份，两边各记各的，数据很快就会分叉，而且没法自动合并。统一一个入口，就永远只有一份数据，没有同步问题。

### 多人一起用

多个账号共用同一个网址，但**数据是各自独立的**：每人有自己每天的生成文章、自己的词汇/复习/素材/作文批改记录。

- 想让谁用：你自己在 **设置 → 用户管理** 里开一个账号（用户名 + 密码，立即可用）；
  或让他上 `/register` 自己申请、你点「批准」
- 不想让谁用了，把那个账号**停用**即可，对方立刻掉线
- 有申请进来时，顶栏的设置入口和用户管理页顶部都会提示「N 条申请待批准」
- 你自己是管理员：能改别人的密码、能批准/拒绝申请，但**看不到别人的学习内容**
- 待批准的人**不会**被算进每日自动生成，也不会计入「系统已有几个账号」
- 每天的自动生成会**给每个在职账号各生成一份**，所以人多了以后早上第一次打开会稍慢，属正常

### 手机上变成 App

用手机浏览器打开后，Edge/Safari 菜单里选「**添加到主屏幕**」。之后图标点开就是全屏，和 App 没区别（这就是当初选 PWA 而不是小程序的意义）。

## 6. 验收清单

部署完我会逐条跑给你看：

- [ ] 打开 `https://你的域名` 出现**登录页**，不是内容页
- [ ] 用初始化码建好管理员账号后，能正常登录
- [ ] 密码输错 → 提示"用户名或密码不对"，且不下发登录凭据
- [ ] 登录成功后一周内不用重复登录（换设备要重新登）
- [ ] 在「用户管理」里给熟人开号后，两人互相看不到对方的数据
- [ ] 熟人在 `/register` 自助申请 → 他登不进去 → 你点「批准」后能登录
- [ ] 未批准/已停用的账号都登不进去
- [ ] 手机 4G/5G 下（不连 WiFi）能正常打开
- [ ] 家里的收藏、素材、作文批改记录**全都在**（老数据会自动归到第一个账号名下）
- [ ] 服务器重启后，服务自动恢复（我会真的重启一次验证）
- [ ] 早上 8 点打开，当天内容已经生成好
- [ ] 备份文件确实产生

## 7. 出问题了怎么办

| 现象 | 大概率原因 | 处理 |
|------|-----------|------|
| 打不开，转圈 | 服务挂了 | `systemctl status kaoyan` 看状态，`journalctl -u kaoyan -n 100` 看日志 |
| 提示证书错误 | 域名解析还没生效 | 等 DNS 生效（最长几小时），`dig 你的域名` 确认 |
| 能打开但没内容 | API Key 没填对 / 余额不足 | 看 `/api/health` 里的 `ai_ready` |
| 忘了初始化码 | — | `cat /opt/kaoyan/data/setup_code.txt`；已经建过账号就无所谓了 |
| 忘了自己的密码 | — | 目前**没有自助找回**。用另一个管理员账号在「用户管理」里重置；如果只有一个管理员且忘了，告诉我，我从数据库层面处理（学习数据不会动） |
| 想加人 / 少人 | — | 「设置 → 用户管理」开号 / 停用；或让对方上 `/register` 申请、你批准。立刻生效，不用重启 |
| 别人的申请一直登不进去 | 还没批准 | 「设置 → 用户管理」顶部点「批准」（这是设计如此，防止陌生人拿注册网址混进来） |
| 忘了共用口令（口令门模式） | — | 改 `/opt/kaoyan/.env` 里的 `ACCESS_PASSWORD`，`systemctl restart kaoyan`，所有设备重新登录 |

## 附：安全提醒

- **`.env` 绝不能提交到任何代码仓库**，里面有你的 API Key 和访问口令。
- 服务器 **只开放 80 / 443 / 22 三个端口**，应用本身只监听 127.0.0.1，不直接对公网暴露（setup 脚本已按此配置）。
- 装好后建议把 root 密码登录关掉，改密钥。我可以帮你配。
