# 错题本优化说明

## 已处理的问题

1. 识别失败与识别不确定内容没有随草稿刷新，用户只看到失败状态。
2. 图片识别在一次网页请求中等待模型，多题或慢请求容易受到公网超时影响。
3. 录题同时要求解题，答案失败会拖累题干录入。
4. 核对保存前就释放原图，无法对照重试；网络波动后重试保存可能重复录题。
5. 英语每日生成没有独立暂停条件。
6. 旧复习规则分别计算每题的工作日，不能保证周末批次与后续批次依次错开；说明也未覆盖 60 天档。

## 错误代码与正确代码对照

以下为关键逻辑的简化示例，完整实现见 `app/` 和 `web/app.js`。

### 失败原因没有显示

原逻辑只更新状态与题干，没有同步草稿中的提示区域：

```js
d.error = error.message;
paintDraftCard(d.key); // 原实现没有刷新错误及待核对内容
```

现在每张卡都有独立提示区域，局部更新时一并同步：

```js
messages.innerHTML = 错误说明 + 待核对内容;
```

错误内容按文本转义后呈现，避免模型输出被当成页面代码执行。识别失败与保存失败使用不同说明，保留题干供重试。

### 图片识别等待过久

旧流程：

```text
上传 → 在同一请求中等待模型完成 → 返回题干
```

新流程：

```text
上传 → 立即返回任务编号 → 后台识别 → 网页查询进度并获取题干
```

任务按账号隔离，相同任务编号重复提交会查询原任务；每个账号限制同时识别的任务数量，旧任务结果会清理。服务重启或结果过期会明确提示重新识别。

### 识图与答案互相阻塞

旧提示要求「没有答案也必须自己解出来」；现在先转录题干和分类，仅摘录明确对应的印刷答案，缺答案也可以保存。保存后通过「让 AI 只算个答案」单独补齐。

临时图片在确认保存前保留在当前页面，保存成功后释放，不写入服务器。页面刷新会清掉尚未保存的临时草稿，因此刷新前请保存。每份草稿带稳定的保存编号，网络波动时再次保存不会重复插入。

### 英语每日更新没有暂停开关

错误条件：

```python
if not settings.ai_ready:
    return None
```

修正条件：

```python
if not settings.english_enabled or not settings.ai_ready:
    return None
```

数学识图仍需 AI，因此通过独立的 `ENGLISH_ENABLED=0` 暂停英语，保留历史数据。前台入口、后台调度、每日生成接口及命令行生成入口一起停用。需要恢复时显式设置为 `1` 并重启。

### 周末复习批次顺延

旧做法只对每道题单独跳过周末，或者将周末日期加两天，原周一的题没有一起顺延。

现在保存 `planned_review`（原计划日期）与 `next_review`（实际日期），将同一原计划日期视为一批：

```text
原周六 → 下周一
原周日 → 下周二
原周一 → 下周三
原周二 → 下周四
后续批次继续跳过周末
```

3 / 7 / 14 / 30 / 60 表示生成原计划的自然日间隔，实际日期根据批次顺延。不同账号、数学和信号分别安排。已公布日期只往后顺延，删除或提前完成一批不会把后面的题突然提前。

周末强制任务为零，自主刷题随时可用。提前练习并提交结果后，用新计划替换旧计划，因此原来那次任务不会再次出现。历史日期已经被旧版本调整过的，沿用已有日期，不推测恢复。
